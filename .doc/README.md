## 规范与使用原则

1. **唯一对应**：每个稳定可验证的具体功能在对应的编号目录中拥有且仅拥有一个编号文件（`<PREFIX>-<三位编号>-<功能名>.md`）。
2. **多对多解耦**：本功能地图与工程层的任务票据（`.project/tickets/`）保持多对多关系。功能地图反映系统耐久形态，工程票据追踪变更过程。
3. **真实证据驱动**：所有文档均基于代码实现路径与已验证运行事实编写，不记录未落地的臆想特性。
