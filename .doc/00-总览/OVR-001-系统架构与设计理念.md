# OVR-001: 系统架构与设计理念

## 用途与可观察行为
OmniVoice 采用 **Diffusion Language Model** 架构，将多语言离散文本 Token、音色指令（Instruct）与离散神经声学标记（Audio Tokens）无缝整合在同一统一的生成框架内。其通过扩散逐步去噪机制预测高保真多码本（Multi-codebook RVQ）声学特征，在兼顾极速推理（RTF 最低达 0.025）的同时，消除传统自回归（AR）模型易产生的幻读、跳字与漏字问题。

## 触发方式
- Python 代码中实例化模型：`OmniVoice.from_pretrained("k2-fsa/OmniVoice")`
- CLI 命令行工具启动：`omnivoice-infer`, `omnivoice-demo`, `omnivoice-infer-batch`
- 训练入口执行：`python -m omnivoice.cli.train`

## 输入与输出
- **输入**：
  - 文本输入（含可选副语言标签与发音注音）
  - 参考音频（WAV/MP3 等，采样率自动重采样）或音色特征描述文本
- **输出**：
  - 24kHz 单声道无损语音波形（NumPy 数组或 WAV 文件）

## 核心架构流程
1. **文本与条件处理**：
   - 文本经分词器（Qwen/Transformers Tokenizer）编码为文本向量。
   - 参考音频由内置神经声码标记器（HiggsAudioV2TokenizerModel）编码为 8 层残差量化（RVQ）离散 Token。
   - 若缺失参考文本，自动通过内置 Whisper 管道完成语音识别转写。
2. **扩散语言模型主体**：
   - 基于 Transformer Backbone，同时挂载多码本声学嵌入层（`audio_embeddings`）与预测头（`audio_heads`）。
   - 在推理阶段，结合无分类器引导（CFG, `guidance_scale`）与自适应调度器对掩码声学 Token 执行 16~32 步迭代去噪。
3. **音频重构**：
   - 将最终去噪收敛的 8 层 Codebook 索引送入 HiggsAudioV2 声码器重构为 24kHz 连续时域语音信号。
   - 经后处理淡入淡出、静音剥除与 RMS 响度规整输出。
