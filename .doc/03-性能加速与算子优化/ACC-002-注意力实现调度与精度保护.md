# ACC-002: 注意力实现调度与精度保护

## 用途与可观察行为
OmniVoice 支持跨多代 GPU、多硬件后端的动态注意力实现自适应切换，包括 PyTorch 内置的 `sdpa` (Scaled Dot-Product Attention)、`flash_attention_2` 以及支持变长打包序列训练的 `flex_attention`。特别针对 PyTorch 混合精度训练中 `flex_attention` 遭遇 fp32 Master Weight 导致内核意外升精度为 fp32 从而造成性能下降约 12x 的顽疾，设计了 `_autocast_flex_attention` 精度保护包装。

## 核心机制与精度保护
1. **Autocast Flex Attention 保护**：
   - Qwen3 等 LLM Backbone 中的 `q_norm`/`k_norm` 在混合精度下以 fp32 运行，可能静默将激活值提升为 fp32。
   - `sdpa` 原生自带 autocast 截断降采样，而原生 `flex_attention` 会以全 fp32 计算注意力，使反向传播由 5.1ms 暴增至 61.8ms。
   - 模型在初始化时检测并注册 `omnivoice_flex_attention`，在 kernel 边界将输入强制下采样至当前 autocast 数据类型（如 bf16/fp16），彻底抹平性能抖动与数值不一致。
2. **硬件跨平台回退**：
   - Intel Arc GPU (XPU)：不支持 `flash_attn`，系统自动优雅降级到 `sdpa`。
   - Apple Silicon (MPS)：`HiggsAudioV2TokenizerModel` 输出通道超 65536，分词器自动转移至 CPU，模型主干保持在 MPS 运行。
