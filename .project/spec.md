# OmniVoice Specification: 分句配音工作室与可移植对照蓝图 (Sentence Studio Reference Blueprint)

## Problem Statement

用户在进行 5~10 分钟长篇文本配音时，当前语音合成系统默认将整篇文本交叉淡入合并为单一超长音频输出。一旦其中某一句出现发音错漏、语气语调不自然或时序偏差，用户无法单独修正该句，必须推倒重跑整篇，且输出的单一大音频在后续视频剪辑与后期软件中极难对齐。此外，大段文本直接粘贴时格式混乱（混杂空行、无序换行），缺乏一站式自动化清洗与分层交互体验。

更重要的是，当前业界缺乏一套解耦度高、交互完善、可作为“标准对照蓝图”直接移植到其他语音合成项目（如 ChatTTS、CosyVoice、F5-TTS）的分句配音与局部重算参考实现。

## Solution

在不破坏原有模型推理与单段合成流程的前提下，构建一套独立解耦的“分句配音工作室（Sentence Studio）”：
1. **智能文本清洗与拆分**：支持一次性粘贴任意格式大段文本，以“行优先（一行一句）”为第一准则，自动剔除空行杂质，无换行时通过句末终结标点智能兜底，结构化拆分出独立句子序列。
2. **全局音色一致性克隆**：用户仅需上传一份参考音频，全局提取并冻结声纹 Prompt 特征，批量复用于所有分句，保证全篇所有句子音色高度一致。
3. **分层列表与单句热重跑**：界面按 `01 文本`、`02 文本` ... 逐行渲染独立播放器与编辑框。用户可现场修改某一行文本，并点击该行专属的“重新生成”按钮单独重跑并热替换音频，无需重算全篇。
4. **序号化全量打包交付**：提供一键“全部打包下载 (ZIP)”，导出的压缩包内包含严格自然排序的文件（如 `01_xxx.wav`, `02_xxx.wav`），方便剪辑师无缝拖拽对齐。
5. **可移植架构蓝图**：核心逻辑层（文本清洗、分句调度、ZIP 打包）与模型推理、UI 交互严格解耦，任何第三方语音项目只需实现标准模型适配器即可整体克隆移植。

## User Stories

1. **作为长视频创作者/剪辑师**，我想一次性粘贴整篇台词，系统自动拆分为一行一句并批量生成独立的编号音频，以便我在剪辑软件中按顺序快速对轨。
2. **作为配音制作人**，我想在生成完毕后逐行试听，当发现某一句语气不合适时，能直接修改该句台词并仅重新生成该句，以便节省大量显卡计算时间与等待成本。
3. **作为声音设计师**，我想只需上传一次参考干声音频，整篇所有分句自动采用完全相同的声纹特征，以便全片旁白音色前后完全统一无违和感。
4. **作为音频工程师**，我想一键下载全部音频的 ZIP 压缩包，解压出来的文件名严格按 `01`、`02` 顺序排列，以便自动化脚本或工程母带按序载入。
5. **作为多项目开发者**，我想把这套分句配音工作室的底层模块和前端交互整体移植到我其他的语音合成模型仓库中，只需对接一个单句生成函数即可直接复用全部能力。

## Implementation Decisions

### 1. 分层解耦架构 (Three-Tier Architecture)
- **核心无依赖层 (Core Studio Engine)**：负责文本清洗分句、分句数据对象定义、ZIP 打包与清单生成。纯标准库与轻量科学计算库，零 UI 与零具体模型绑定。
- **模型适配器接口 (TTS Model Adapter Protocol)**：定义抽象调用协议 `generate_sentence(text, prompt, config) -> waveform`，实现具体 TTS 框架与分句调度器的隔离。
- **交互展现层 (Web Studio UI)**：以独立的模块化 Tab 形式挂载入 WebUI，内部管理分句列表状态、单句更新事件流与文件流打包，保证独立插拔。

### 2. 数据结构契约 (Sentence Data Contract)
每个分句单元采用不可变索引与可变状态结构：
- `index`: 整数序号 (1, 2, 3...)，格式化输出固定为补零两位/三位数 (01, 02...)。
- `raw_text`: 初始清洗拆分出的文本。
- `current_text`: 用户在界面上修改后的当前文本。
- `waveform`: 生成的 `np.ndarray` (24kHz, float32 或 int16)。
- `sample_rate`: 恒定 24,000 Hz。
- `duration`: 音频实际时长（秒）。
- `status`: 状态机枚举 (`pending` -> `generating` -> `done` / `error`)。

### 3. 文本清洗与拆分规则契约 (Text Normalization & Chunking Contract)
- **规则 1（换行优先）**：若文本中包含有效换行符 `\n`，按换行拆分；剥离每行首尾空白，完全剔除纯空白行。
- **规则 2（无换行兜底）**：若用户输入文本无换行或仅单行长文本，按预定义终结符集合（`。！？.!?`）执行断句，保留末尾标点。
- **规则 3（连句保持）**：逗号 `，`、顿号 `、`、分号 `；` 视为句内连句停顿，严禁拆开。
- **规则 4（极短句自愈）**：单行若仅有孤立标点或字符长度 < 1，予以过滤忽略。

### 4. 交付与导出命名契约 (Packaging & Naming Contract)
- 导出压缩包内文件名格式：`{index:02d}_{sanitized_text[:15]}.wav`（如 `01_今天天气真好.wav`）。
- 压缩包根目录附带 `manifest.json` 与 `list.txt`，记录索引、文本与对应文件名，适配各类视频对齐工具。

## Out of Scope

- 不在本次迭代中引入带时间轴的 SRT 字幕导出（后续在字幕模块统一实现）。
- 不改变底层扩散模型的训练结构或权重格式。
- 不影响现有“声音克隆”、“音色设计”、“角色管理”等已有 Tab 的原有流程与功能。
